# Viewer-bound receive bodies — P1.2/G1 increment

Status: snapshot/event/result body schema and matching Java/C# validation now
run before the dummy client deserializes a snapshot. Local evidence only;
protocol freeze, licensed Unity CI and live gateway privacy remain pending.

## Reuse the existing DTOs

`wire-receive-v1.schema.json` is generated by `tools/generate_play_models.py` from
the existing envelope and Python DTO schema. Snapshot and result bodies contain
exactly fixture_only (boolean) and snapshot (the existing GameSnapshot). Events
contain exactly fixture_only, session_id, viewer_id and the existing GameEvent.
No second game-state or persistent deck model is introduced.

A result uses the full existing snapshot and requires status `finished` and a
nonempty string result. It is not a command acknowledgement. The dummy result
remains `fixture_complete` with fixture_only=true; it is never a real engine
outcome or evidence of natural game completion. Future actual result values
must remain engine-reported and must not be interpreted as new rules by Unity.

The generator also emits internal `ReceiveContractSchema` data for Java/C# from
the same DTO schema, with a source hash. Do not edit generated files. The receive
readers interpret only this fixed, reviewed schema subset, not arbitrary schemas
sent by a gateway. Generation rejects unsupported source keywords; these readers
are not general JSON Schema implementations. Existing generated DTOs are intact.

## Validation before use

`ReceiveMessages.Parse/parse` first runs bounded strict envelope parsing, then:

- Requires the exact message/body shape and explicit boolean fixture marker.
- Validates every nested DTO field against the generated fixed schema, preserving
  nullable/required distinctions, tuple shapes, protocol version and integer types.
- Rejects unknown fields and the existing schema's concealed GameObject identity,
  characteristics/commander/copy links and hidden observation printing/name fields.
- Requires session and viewer to match the caller's authenticated context.
- Rejects revisions older than the caller's supplied minimum; equal revisions
  are permitted, so this is not replay/idempotency tracking or event ordering.
- Rejects empty/duplicate player, object and action IDs within their arrays.
- Binds a non-null decision's player to the receiving viewer.
- Requires terminal status/nonempty result for result messages.

The default C# fixtureMode is false; Java callers pass the expected mode
explicitly. A production context must refuse fixture_only=true. Setting that
flag in a packet does not grant permission to enable fixture mode. The dummy
harness explicitly opts in; production-mode corpus samples are synthetic shape
tests, not captures from a real engine.

Event.player_id identifies an actor and may differ from the authenticated
recipient. The outer viewer_id identifies the recipient; never substitute the
actor as authorization. Empty player arrays in failed baseline snapshots remain
supported. No seat count, Magic legality or inferred card facts are added.

Checks return only safe RECEIVE_SHAPE, RECEIVE_MODE, RECEIVE_UNSUPPORTED,
RECEIVE_CONTEXT, RECEIVE_SESSION, RECEIVE_VIEWER or RECEIVE_REVISION categories.
Invalid frames are rejected before DTO deserialization. Blocking/validation work
belongs on transport workers. Returned JSON trees remain mutable intermediate
data; an immutable per-viewer scene projection is still required.

## What this does not prove

The checks enforce explicit concealment flags and trusted context, not a complete
engine visibility policy. A malicious gateway could lie about those flags or put
secrets in ordinary strings. The real gateway must still filter root state and
private reveals before serialization; Unity must clear private cached resources
and reject unauthorized context changes. Do not recreate visibility from zones
or printed information in this reader. Validating a received result does not
prove its sender observed the engine, and authenticating a viewer key does not
prove the gateway's actual installed engine/artifact pin.

Remaining transport work includes command/ACK replay tracking, uncertain outcomes,
all existing choice families, version/unknown-field evolution, queue limits,
cancellation and product bootstrap/ownership containment. G1 stays open.

## Evidence

The shared `fixtures/wire-receive-v1.json` includes eight positive and 24 negative
cases. It reuses the original snapshot fixtures, including failed/empty-player
state, and rejects unknown/malformed fields, wrong session/viewer, stale revisions,
private identity/observation leaks, duplicate object IDs and fixture spoofing.
Python checks distinguish schema validity from context/freshness checks.

The actual Java↔Unity EditMode exchange now validates outbound and inbound
snapshot/event/result messages. It also exercises a different event actor,
a concealed object and a terminal DTO while retaining the earlier authentication,
stale/pending rejection and shutdown assertions.

Local validation: Java corpora passed, 42 Unity EditMode checks passed (including
three owned-process exchanges), five focused Python schema checks passed and
generated artifacts match. No full local suite, real engine run, screenshot or
